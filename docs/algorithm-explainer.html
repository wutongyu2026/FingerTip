FingerTip 算法说明

四个行为指标 + 音乐/图像本地生成算法 · 全部摘自真实代码（v0.3.10）

一、四个行为指标（summary/aggregator.rs · compute_metrics）

输入 = 当日按键事件流 events + 24 小时分桶 hourly[24]。所有除零一律返回 0。

密集度 intensity
total_keys ÷ active_hours
≥800 快 · 0<x<800 慢
active_hours = 有按键的小时数
平稳度 steadiness
stddev(hourly) ÷ mean(hourly)
≤0.8 平稳 · >0.8 跳跃
变异系数；mean/std 按 24 桶（含空小时）
流畅度 fluency
pauses(>2s) ÷ (events−1)
<10% 流畅 · ≥10% 停顿
相邻键间隔>2s 记一次停顿
活跃度 activity
count(hourly[i] > 0)
>4h 活跃 · ≤4h 不活跃
有按键的小时数

平稳度细节（为何截图 4.80 = 跳跃）

截图里 平稳度 4.80：当天按键集中在 1 个小时，24 桶里 23 个为 0， 标准差远大于均值 → 变异系数 4.8 > 0.8，判定「跳跃」。若 24 小时完全均匀，该值≈0（平稳）。

高峰按键（第 5 张卡）

= 当日 单个最常按的键 的次数（Top5[0].count）。截图 6 = 最忙的键按了 6 次。 注意它与 hero 的「峰值小时」不同：后者是按键最多的小时（argmax hourly）。

二、音乐生成（generate/local/music.rs + db/wav_encoder.rs）

mood → BPMevents → notesevents → 64 振幅theme_word → 缩放
步骤算法
BPMcalm/tired/sad=75 · happy/excited=130 · energetic/focused=140 · angry=155 · 其它=100
时长max(末键−首键, 8000ms)；无事件 = 16 拍
音符 notes取前 64 个事件，velocity=80，start=该键时间−首键，dur=半拍
振幅 amplitudes事件按时间分 64 桶 → 每桶计数÷最大计数 → ×theme_factor，clamp [0,1]
theme_factor(theme_word 字节和 % 50)/100 + 0.75 ∈ [0.75,1.25]（同 mood 不同词波形不同）
WAV 渲染单声道 16-bit 44.1kHz 正弦波；键码→MIDI→频率
freq = 440 × 2^((midi − 69) / 12)
键码→MIDI: A-G→60/62/64/65/67/69/71  0-9→72-81  空格→72  其它→60
振幅 = velocity/127 × 0.5
确定性算法：同一天的 events+mood+theme_word 永远产出同一首曲子，无随机数。

三、图像生成（generate/local/art.rs）

mood → 基础色相theme_word → 色相+散布events → 坐标种子
步骤算法
画布256×256，固定 64 个像素块（每块前端画 4×4）
基础色相happy/energetic=30(橙) · calm=120(绿) · sad=210(蓝) · angry=0(红) · focused=250(紫) · 其它=60
每像素色相h = (基础色相 + theme_word[i%len] 的字节值) % 360，再 HSV(h,0.7,0.85)→RGB
坐标seed = events[i%len].key_code + 字符值（无事件=i×7）
x = (seed×31 + i×97) % 256 · y = (seed×17 + i×53) % 256
mood 定色调、theme_word 调色+移位、events 定散布 —— 三者任一变化，画面就不同。

四、数据链路一句话

键盘 Hook → SQLite key_events → scheduler 每 60s 聚合 → daily_summary（四指标+Top5+hourly）→ 前端 Today 渲染；生成时 generate_now 读 events 本地算 Music/Art → 写 WAV/PNG 到 app_data_dir/downloads/{date}/ → Artworks 播放/下载/二维码分享。
