## 1. Business Problem（业务问题）

**世界发生了什么变化，创造了值得解决的问题？**

- **变化**：个人量化（Quantified Self）运动兴起 + AI 生成内容（AIGC）大众化
- **现状缺口**：用户拥有"看自己数字生活"的工具（屏幕时间、心率、睡眠、步数），但**键盘输入行为**仍是盲区——每天敲击数千次，却没有任何方式量化或表达
- **为什么现在重要**：AIGC 让"把数据变成可消费的艺术品"成本骤降，使"输入即作品"成为可能；但市面上无成熟产品占据这个缝隙

## 2. Business Outcomes（业务结果）

**如何知道问题被解决了？测量什么行为变化？**

- **首版（自用验证阶段）**：不预设量化指标，**仅验证"能否跑通"** —— 即：连续运行不崩 + 数据能落到 SQLite + AI 生成管线能产出文件
- **后续阶段（待评估）**：留待首版实验完成后再定义

> 注：Box 2 是行为变化指标，Box 4 才是情感/收益。首版故意让 Box 2 留白，避免"自用项目"的伪 KPI 化。

## 3. Users（用户）

**首先聚焦哪些 persona？**

- **首版焦点**：开发者本人（具备技术能力与隐私意识的早期使用者）
- **后续可能拓展**（不在首版范围）：创意工作者、写作者、键盘爱好者、Quantified Self 群体

> 注：首版不预设外部用户群体，遵循 YAGNI；待自用验证通过后再启动 persona 研究。

## 4. User Outcomes & Benefits（用户成果与收益）

**用户为什么会寻求这个产品？获得什么好处？**

| 用户收益 | 实现机制 |
|---|---|
| **看见** 一天的键盘"指纹" | 日总结卡片：按键次数、占比、时段分布、停顿、删除/修改模式 |
| **听见** 自己的输入节奏 | AI 音乐生成（首版纯音乐） |
| **看见色彩** —— 输入行为映射为艺术 | 数字画作（抽象表现主义风格，静态 PNG） |
| **安全感** —— 数据不出本机 | 纯本地存储 + AI 仅接收抽象参数 |

## 5. Solutions（候选方案）

**什么能同时解决业务问题并满足用户需求？**

### 已选方案（首版实施）
1. **核心方案**：Tauri 后台监听 + SQLite 聚合 + AI 适配层（MiniMax 云 + 本地可选）

### 备选方案（已评估但不采用）
2. ~~轻量替代~~：纯前端 Web 应用，仅记录浏览器内输入 —— 实用性差，否决
3. ~~不采集方案~~：仅基于"心情词 + 偏好风格"用 AI 随机生成 —— 丢失"键盘指纹"核心价值，否决

### 后续候选（不在首版）
4. 带歌词音乐 —— 需独立隐私评估后启用
5. macOS / Linux 原生打包
6. 历史可视化（热力图、趋势线）
7. 自定义 prompt 模板

## 6. Hypotheses（假设）

**用可测试的格式串联 Box 2-5：**

> **H1**：我们相信"开发者连续 7 天自用跑通"这一业务结果，将通过开发者本人获得"看见/听见/感受一天输入节奏"的情感收益，借助"后台静默监听 + 日总结 + AI 音乐/画作"方案实现。

> **H2**：我们相信"开发者主动查看主窗口 ≥ 5 次/周"这一行为变化，将通过开发者获得"对自身输入行为的新认知"实现，借助"日总结卡片 + 主题词"方案。

> **H3**：我们相信"开发者愿意长期保留应用"这一留存信号，将通过开发者获得"隐私安全感"实现，借助"纯本地存储 + AI 抽象参数传递"方案。

## 7. What's Most Important to Learn First?（最重要的学习点）

**最关键的假设 → 价值风险**：用户（开发者本人）真的**想看**自己的键盘节奏吗？

- **风险类型**：Value（价值）> Feasibility（可行性）
- **理由**：即使技术 100% 可行（rdev Hook 稳定、AI 生成可用、SQLite 写入正常），若自用 7 天后没有"主动想看"的冲动，整个项目的核心价值就不成立
- **此阶段优先 value 风险而非 feasibility 风险**：避免在"用户根本不想看的东西"上浪费工程投入

## 8. Least Work to Learn Next?（最小验证实验）

**用最小工作量验证/证伪 Box 7 的假设：**

- **实验设计**：开发者本人**安装并自用 7 天**
- **观测指标**：
  1. 是否主动打开过主窗口？（每日 是/否）
  2. 看到日总结时第一反应是什么？（每日一句话记录）
  3. 是否完成过"提交心情词 → 生成音乐 + 画作"全流程？（每日 是/否）
- **成功标准（粗略）**：7 天中 ≥ 3 天主动打开主窗口，且至少完成 1 次完整生成
- **时间盒**：2 周（含首日部署、配置、跑通）
- **若假设被证伪**：回到 Box 7，重新识别最关键假设，可能是"用户想要音乐"或"用户想要画作"，分别验证
